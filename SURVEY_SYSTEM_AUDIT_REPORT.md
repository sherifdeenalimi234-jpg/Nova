# SURVEY SYSTEM ARCHITECTURE, DATABASE & INITIALIZATION AUDIT REPORT

## 1. Current Architecture Documentation
The survey initialization system is hosted at `app/creator/surveys/new/page.tsx`. It is a client-side React component that captures basic metadata (Title, Overview) and interfaces with the `createSurvey` server action in `lib/actions/surveys.ts`. The architecture successfully isolates the "Initialization" phase from the "Building" phase.

## 2. Legacy Survey Architect Dependency Map
The Initialization page is a refactored version of the legacy "Survey Architect". It retains structural dependencies but has been functionally decoupled:
```text
[Initialization Page]
   ├─> [Next.js Router] -> Redirection to Builder
   ├─> [Lucide Icons] -> UI Elements
   ├─> [Server Action: createSurvey] -> Database Insertion
   └─> [Supabase SDK] -> Data Persistence
```
*Note: Unused legacy imports (Reorder, AnimatePresence) are still present in the file but do not execute.*

## 3. Initialization Workflow Documentation
1.  **Entry:** User navigates to `/creator/surveys/new`.
2.  **Input:** User provides `Initialization Title` and `Objective Overview`.
3.  **Action:** User clicks "Create Survey".
4.  **Process:** `handleCreate` triggers the `createSurvey` server action.
5.  **Redirect:** On success, the application redirects to `/creator/surveys/[id]/builder`.

## 4. Data Flow Documentation
```text
[Frontend Form (page.tsx)]
       ↓ (title, description)
[Server Action (createSurvey)]
       ↓ (creator_id, title, description, settings, status='draft')
[PostgreSQL (surveys table)]
       ↓ (returns record + generated UUID)
[Frontend Callback]
       ↓ (res.data.id)
[Router Redirect] -> /creator/surveys/[id]/builder
```

## 5. Database Insert Documentation
The insert operation targets the `public.surveys` table.
- **Table:** `public.surveys`
- **Payload:**
  - `creator_id`: Authenticated User ID
  - `title`: User Input (Title)
  - `description`: User Input (Overview)
  - `status`: 'draft' (Hardcoded for initialization)
  - `settings`: Default JSONB object

## 6. Survey ID Generation Documentation
Survey IDs are generated by PostgreSQL using `gen_random_uuid()` during the insert operation. The `createSurvey` action explicitly selects and returns the `id` of the new row using `.select().single()`.
- **Generated ID Type:** UUID v4
- **Verification:** The ID is successfully returned to the client and used in the redirect URL.

## 7. Routing Documentation
- **Initialization Route:** `/creator/surveys/new`
- **Redirect Path:** `/creator/surveys/[id]/builder`
- **Routing Logic:** Handled by `next/navigation`'s `useRouter`.
- **Verification:** Routes are correctly mapped and functional.

## 8. Dashboard Documentation
The Survey Dashboard (Builder) is located at `app/creator/surveys/[id]/builder/page.tsx`. It is a dynamic route that fetches the full survey tree (including questions and options) based on the ID generated during initialization.

## 9. Runtime Error Documentation
No active runtime errors were observed during initialization. However, a potential **namespace collision** was identified in the `getSurveyForBuilder` query where a JSONB column named `questions` conflicted with a join alias of the same name. This has been identified for resolution via column renaming.

## 10. Database Schema Documentation
- **Table `surveys`:** `id`, `creator_id`, `title`, `description`, `status`, `category`, `cover_image`, `estimated_time`, `tags`, `settings`, `legacy_questions`, `created_at`, `updated_at`.
- **Table `survey_questions`:** `id`, `survey_id`, `type`, `title`, `description`, `is_required`, `order_index`, `placeholder`, `validation_rules`, `created_at`, `updated_at`.
- **Table `survey_options`:** `id`, `question_id`, `text`, `order_index`, `created_at`, `updated_at`.

## 11. Required SQL Documentation
To resolve the identified namespace collision and align the schema with the codebase, the following SQL is required:

```sql
-- Resolve Namespace Collision in Surveys Table
ALTER TABLE public.surveys RENAME COLUMN questions TO legacy_questions;
ALTER TABLE public.surveys ALTER COLUMN legacy_questions DROP NOT NULL;

-- Correct Survey Responses Table Naming
ALTER TABLE public.survey_responses RENAME COLUMN user_id TO participant_id;
ALTER TABLE public.survey_responses RENAME COLUMN answers TO responses;
```

## 12. Required Migration Documentation
A new migration file `20240621000000_survey_schema_correction.sql` should be created containing the SQL from Section 11 to ensure consistency across environments.

## 13. Root Cause Analysis
The perceived "failures" in the survey system were not due to initialization data loss, but rather a **Fetch Failure** in the Dashboard. The `getSurveyForBuilder` query was failing to correctly map questions because the database had a JSONB column named `questions` that overshadowed the join to the `survey_questions` table.

## 14. Refactor Recommendation Plan
1.  **Execute SQL Migration:** Rename `surveys.questions` to `legacy_questions`.
2.  **Cleanup Frontend:** Remove unused imports from `app/creator/surveys/new/page.tsx`.
3.  **Standardize Server Actions:** Update `submitSurveyResponse` to use the corrected column names (`participant_id`, `responses`).
